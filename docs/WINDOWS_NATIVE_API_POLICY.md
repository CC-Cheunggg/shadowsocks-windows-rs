# Windows native API policy

This policy is normative for Windows implementation work in this repository.

## Native-first rule

Product code, recovery tools, and automated test executables MUST use a
documented Windows API whenever that API can implement the required operation.
They MUST NOT substitute a spawned PowerShell, `pwsh`, `netsh.exe`,
`route.exe`, `wmic.exe`, or similar command-line process for an available
Win32/WinSock/IP Helper API.

The current networking mapping is:

| Operation | Required API family |
| --- | --- |
| enumerate routes | `GetIpForwardTable2` |
| choose the route and source for one destination | `GetBestRoute2` |
| create/delete an owned route | `CreateIpForwardEntry2` / `DeleteIpForwardEntry2` |
| enumerate/create/delete unicast addresses | `GetUnicastIpAddressTable` / `CreateUnicastIpAddressEntry` / `DeleteUnicastIpAddressEntry` |
| read or set interface metric/MTU | `GetIpInterfaceEntry` / `SetIpInterfaceEntry` |
| enumerate adapters, addresses, gateways, and configured DNS servers | `GetAdaptersAddresses` and IP Helper tables |
| bind DIRECT sockets to the physical interface | WinSock `setsockopt`, `bind`, and related socket APIs |
| Wintun adapter and packet rings | the pinned application-local official `wintun.dll` API |

Production recovery MUST use the same native ownership identities and deletion
APIs as normal shutdown. Human-readable PowerShell recovery examples are not a
replacement for `network_recover.exe`.

## Allowed command-line use

PowerShell may be used outside the product process for:

- GitHub Actions orchestration, artifact staging, and independent assertions;
- operator-run, read-only acceptance diagnostics such as `Get-NetRoute`;
- an operation for which no supported native API exists on the minimum
  supported Windows version.

The last category is an exception, not a convenience. Every exception MUST:

1. identify the missing native API and supported-OS constraint in this file;
2. use fixed executable and argument identities rather than caller-controlled
   script or filesystem paths;
3. define timeout, cancellation, partial-failure, and rollback behavior;
4. have Windows tests for success, failure, and cleanup; and
5. be approved during review before it is merged.

There are currently no approved PowerShell exceptions for runtime network
inspection or mutation.

## Review and CI gate

CI rejects Rust product and test source containing executable tokens for
PowerShell, `pwsh`, `netsh.exe`, `route.exe`, or `wmic.exe`, as well as the
network-inspection and mutation cmdlets previously generated by the runtime and
smoke test. A narrow allow-list may cover only a reviewed exception recorded
above.

GitHub Actions may use PowerShell as the outer orchestration shell and for
independent read-only assertions. The runtime, `network_recover`, and
`wintun_smoke` must share the native platform layer for all route, address,
interface, and recovery operations before the first real full-route Windows
acceptance run.
